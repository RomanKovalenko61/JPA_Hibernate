Из комментариев

Вот один и тот же запрос — выборка name и avgGrade из таблицы Student — в трёх вариантах:

Object[] (устаревший стиль),
Tuple (полу-современный),
record DTO (современный и лучший).
1. Старый стиль — Object[]

```
CriteriaBuilder cb = entityManager.getCriteriaBuilder();
CriteriaQuery<Object[]> query = cb.createQuery(Object[].class);
Root<Student> root = query.from(Student.class);

query.select(cb.array(
root.get("name"),
root.get("avgGrade")
));

List<Object[]> results = entityManager.createQuery(query).getResultList();

for (Object[] row : results) {
String name = (String) row[0];
Double avgGrade = (Double) row[1];
System.out.println(name + " — " + avgGrade);
}
```

Возвращает List<Object[]>, то есть список массивов.
Работает, но нельзя узнать, что внутри, без жёстких индексов.
IDE и компилятор не помогут — ты сам следишь, что [0] это name, а [1] — avgGrade.
Траблы: 🧨 При изменении порядка полей легко ошибиться.

************************************************​​​​​​​************​​​​​​​************​​​​​​​************
2. Средний уровень — Tuple

````
CriteriaBuilder cb = entityManager.getCriteriaBuilder();
CriteriaQuery<Tuple> query = cb.createTupleQuery();
Root<Student> root = query.from(Student.class);

query.multiselect(
root.get("name").alias("name"),
root.get("avgGrade").alias("avgGrade")
);

List<Tuple> results = entityManager.createQuery(query).getResultList();

for (Tuple tuple : results) {
String name = tuple.get("name", String.class);
Double avgGrade = tuple.get("avgGrade", Double.class);
System.out.println(name + " — " + avgGrade);
}
````

Возвращает List<Tuple>, где Tuple = “именованный Object[]”.
Можно получать значения по alias, а не по индексу — это уже плюс.
Но всё ещё нет строгой типизации — Tuple универсальный контейнер.
✅ Лучше читается, особенно если полей много.
🚫 Но не подходит для передачи данных вне слоя DAO (например, в REST-контроллер).

************​​​​​​​************​​​​​​​************​​​​​​​************​​​​​​​************​​​​​​​************​​​​​​​************
3. Современный уровень — record DTO
````
public record StudentInfo(String name, double avgGrade) {}

CriteriaBuilder cb = entityManager.getCriteriaBuilder();
CriteriaQuery<StudentInfo> query = cb.createQuery(StudentInfo.class);
Root<Student> root = query.from(Student.class);

query.select(cb.construct(
StudentInfo.class,
root.get("name"),
root.get("avgGrade")
));

List<StudentInfo> results = entityManager.createQuery(query).getResultList();

for (StudentInfo info : results) {
System.out.println(info.name() + " — " + info.avgGrade());
}
````

Используется criteriaBuilder.construct(), который создаёт DTO напрямую.
Возвращает List<StudentInfo> — типобезопасный и чистый результат.
Поля сопоставляются по порядку параметров конструктора (или record-компонентов).
Идеально подходит для проекций и REST-ответов.
✅ Никаких alias, Tuple, Object[] — сразу готовый объект.
✅ Поддерживается Hibernate 6+ и Jakarta Persistence 3.1/3.2.
🚀 Это “золотой стандарт” современного JPA-кода.

4) есть еще четвёртый вариант: JPQL + SELECT new DTO(...).
   Он короче, чем Criteria API, и идеально подходит, когда запрос простой.

JPQL с конструкцией new
````
public record StudentInfo(String name, double avgGrade) {}

List<StudentInfo> results = entityManager.createQuery(
"SELECT new com.example.StudentInfo(s.name, s.avgGrade) FROM Student s",
StudentInfo.class
).getResultList();

for (StudentInfo info : results) {
System.out.println(info.name() + " — " + info.avgGrade());
}
````

✔️  SELECT new com.example.StudentInfo(...) — это JPQL-проекция.
✔️ JPA сам вызывает конструктор StudentInfo(String, double) и создаёт DTO.
✔️  Имя класса должно быть полным (FQN) — package + имя класса.
✔️  Порядок аргументов в SELECT new ... должен совпадать с порядком в конструкторе или record-компонентах.
✔️  StudentInfo.class передаётся в createQuery() — для типобезопасного результата.

✅ ✚ Преимущества:

Максимально читаемо — чистый JPQL, без CriteriaBuilder.
Типобезопасно — возвращается List<StudentInfo>.
Работает даже в старых версиях JPA (с JPA 2.0 и выше).
Можно добавлять WHERE, JOIN, ORDER BY и т.п. — всё как в обычном SQL.
❌ Минусы:

Строковый запрос (компилятор не проверяет имена полей).
Если переименуешь поле или класс — можно словить QuerySyntaxException.
Поэтому на больших проектах — часто комбинируют:
Criteria для динамических фильтров, а JPQL для простых DTO-запросов.
